CardScout v100 CORE3 STABLE — scanner audit

GOAL
Only identify: 1) card name, 2) collector/card number, 3) set.
No attack text, rules text, HP/body OCR, price OCR or automatic 1st Edition OCR.

ROOT CAUSE FOUND
- v77 preserved the coordinate system of guided camera photos. A live camera photo was already cropped by guideSourceRect().
- v81 changed makeOcrCanvas() so yellow-card auto-crop was also applied to guided camera photos. That silently changed the zoom/coordinate system. Fixed percentage ROIs for name/number then moved relative to the card.
- Later versions repeatedly changed loadPhotoFile / makeOcrCanvas / scanCurrentPhoto / name crops. This created regressions where fixing one era broke another.
- v77 accuracy was better but slow because it could OCR: name ROI + header ROI + enhanced top ROI + entire card fallback + many collector-number passes + broad bottom fallback. This also read attack/body text, which is unnecessary.
- v90 visual fingerprinting was not a production-grade visual model and was correctly rejected.

V100 DECISION
- Camera capture + makeOcrCanvas are frozen from v77.
- Guided camera coordinates stay exactly as v77. Yellow-border auto-crop is used only for gallery photos, exactly as in v77.
- Exactly two OCR recognize() calls in scanCurrentPhoto():
  A. v77 top/title ROIs batched into one composite image
  B. v77 bottom collector-number ROIs batched into one composite image
- Each OCR call receives a composite of multiple preprocessing variants of that SAME legal ROI. This improves robustness without OCR-ing attacks/body text.
- Exact database reconciliation is stronger than fuzzy OCR.
- Set total (e.g. /111) is used to scope the set. Set-symbol matching is only a tie-breaker and may never override an exact name+collector DB match.
- No name-only guess is allowed to invent set/number.

DEBUG
- Every incomplete scan is automatically stored locally in localStorage.
- The log contains build, timestamp, source, scan time, only name/number OCR snippets, parsed fields, reason, and a small thumbnail.
- UI button 'Download foutlog' exports cardscout-failed-scans-YYYY-MM-DD.json.
- 'Foute scan opslaan' lets a user record a scan that looked successful but was wrong.
- Max 40 entries are retained to stay within browser storage limits.
